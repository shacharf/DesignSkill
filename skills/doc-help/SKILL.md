description: Explain the docagent workflow, skills, direct commands, file locations, saving, TODO tracking, and recovery; use for design-workflow help rather than document synthesis.
---

Every document we author is human-readable first, including design pages, source summaries, brainstorming records, decisions, TODOs, working summaries, and help. State its purpose, provide the context needed to understand it, use plain language, and introduce ideas progressively. Keep essential meaning visible in the document body; metadata supports tools and must not be the only place a reader can find a task’s motivation, a decision’s status, or necessary context. Preserve original input files unchanged; machine runtime files are separate from authored documents.

Choose the format that makes the idea easiest to understand. Use concise, complete bullets for distinct ideas, short prose for explanations that need continuity, and tables for comparisons. Add a figure, diagram, or example when it clarifies structure, relationships, sequence, or behavior. Give figures clear labels and a short explanation of what the reader should notice; keep them at the page’s level of detail. Avoid dense paragraphs, fragmented bullet inventories, and decorative figures.

Use `docagent help` for an immediate workflow and command reference; it works outside a project and does not invoke a model. Use `docagent COMMAND --help` for exact arguments. Read `DOC_WORKFLOW.md` for examples and recovery. Answer the user's particular question briefly; inspect project state only when needed for a project-specific answer.

Explain the division: skills understand and write; docagent performs deterministic local bookkeeping; Markdown remains authoritative. Typical flow: doc-sources understands inputs, doc-design shapes the main story and selects a module, doc-brainstorm resolves questions, doc-write builds the explanation, and doc-review checks it. This is a flexible workflow, not a mandatory pipeline.

Files: `README.md` is the project entry point and links to `design.md` for the main design ideas; `modules/` holds the hierarchy; `sources/` holds original references and extraction notes; `discussions/` holds reasoning; `TODO.md` holds pending/active/done work; `WORK.md` holds the brief and active pointers. `.docagent/` contains generated configuration, journals, installation records, and search state.

Direct commands do not summarize conversation. Skill-assisted switching saves first; direct module selection only changes focus and clears a discussion belonging to a different module. TODO start retains the task and opens/resumes a discussion. Only the current top-level topic can acquire subtopics. Future subtopics do not exist yet; task count is unlimited. TODO done requires a saved outcome; closing a parent also requires a linked cumulative summary in WORK.md. Unfinished questions are tracked through existing or new follow-up TODOs, with explicit reasons for deferral or retirement. Completed topics remain in history. Saved Markdown can be current while search is pending. `index status` diagnoses freshness; `index flush` retries explicitly. Never imply a checkpoint recovered conversation-only material or that URL registration downloaded a source.

Delegation is optional and performed by the host agent. Suitable substantial extraction, editorial tasks, and bounded reviews can use one or two lower-cost workers; the main agent owns design decisions and integration. See the Delegation section in project AGENTS.md for model/effort selection, context limits, and fallback behavior. `docagent` commands remain deterministic. Explain that worker overhead can increase total usage; do not promise cost savings or imply an unsupported host/model is available.

Progressive planning uses doc-brainstorm in two modes: prepare the top-level agenda/current topic, or work through one saved question. `todo --show ID` loads its full brief and planning context; `todo --next` stays within the current topic or asks for planning/closure. A model recommendation is a handoff suggestion, not an automatic model switch. The fresh main session can perform normal save/bookkeeping operations even when it uses a cheaper model.
