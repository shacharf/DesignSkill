# Design collaboration

Every document we author is human-readable first, including design pages, source summaries, brainstorming records, decisions, TODOs, working summaries, and help. State its purpose, provide the context needed to understand it, use plain language, and introduce ideas progressively. Keep essential meaning visible in the document body; metadata supports tools and must not be the only place a reader can find a task’s motivation, a decision’s status, or necessary context. Preserve original input files unchanged; machine runtime files are separate from authored documents.

Choose the format that makes the idea easiest to understand. Use concise, complete bullets for distinct ideas, short prose for explanations that need continuity, and tables for comparisons. Add a figure, diagram, or example when it clarifies structure, relationships, sequence, or behavior. Give figures clear labels and a short explanation of what the reader should notice; keep them at the page’s level of detail. Avoid dense paragraphs, fragmented bullet inventories, and decorative figures.

Use `docagent status` to resume saved focus. Markdown is authoritative. `README.md` introduces the project and links to the design. `design.md` explains the main ideas; modules form a hierarchy of progressively deeper explanations. Each module should make sense independently with minimal context. Aim for three to five peer concepts; keep exhaustive detail at the leaves without losing constraints.

Use doc-design to guide/save/resume, doc-sources to extract inputs, doc-brainstorm to explore choices, doc-write to explain the design, doc-review to assess it, and doc-help for guidance. Direct CLI commands perform bookkeeping without inference. Source notes, working discussions, and reader-facing design pages have distinct purposes. Clearly distinguish source statements, assumptions, proposals, and accepted decisions.

Maintain pending/active/done work in TODO.md. Preserve motivations and user ordering. Save reasoning and bounded resumes at meaningful checkpoints and before switching or ending. Run `docagent checkpoint` after manual changes. A direct selection cannot summarize unsaved conversation. Search is project-scoped and may lag saved files; use `index status` and `index flush` for recovery. Do not overwrite source originals, manual edits, or silently migrate research projects. Do not run automatic Git operations. See DOC_WORKFLOW.md for commands and recovery.

After substantial drafting or revision, use doc-review on the changed explanation and affected connections. Check readability, ambiguity, missing behavior, and consistency at the appropriate level of detail. Record unresolved findings as questions or TODOs; do not invent answers. At major milestones, review the overall design for cross-module consistency. Small wording changes need no full review.

## Progressive agenda and completion

Use doc-brainstorm to prepare the agenda and discuss individual topics. TODO.md has unlimited top-level topics and at most one level of subtopics. Create details only for the current topic; future topics initially have just their purpose and known dependencies. Read WORK.md's cumulative planning summary and relevant prior outcomes before planning the next topic. Prepare each current subtopic's readable discussion brief before handoff. `todo --show ID` retrieves that full context; `todo --next` does not advance to another parent automatically.

Completion requires an adequate saved outcome, reasoning, design updates where appropriate, and a handoff. Revisit original and newly found questions, reuse/update existing TODOs, and create linked follow-ups for incomplete decisions. Defer only with an open follow-up and a reason; drop obsolete work with a reason. Close children before their parent. Update WORK.md's bounded cumulative summary and link the parent outcome before closing it. Preserve detailed history in discussions. Replan whenever assumptions change; do not erase useful work or preplan all future branches.

Recommend model/effort and a fresh chat when useful for a topic, with a short reason and resume prompt. The user controls the active chat's model and context; docagent stores records. A fresh lower-cost main session can maintain its own records; restrictions below apply to delegated workers only.

## Delegation

Delegate substantial, independent source extraction, editorial work, or bounded review when this is likely to reduce total work or provide a useful independent check. Handle small tasks directly. Run deterministic operations through `docagent`; architecture, conflicting evidence, hierarchy changes, and final integration remain with the main agent.

- Use at most two workers at a time, within the host's limit. On Codex, explicitly request `gpt-6-luna` with `low` reasoning effort for straightforward extraction or wording, and `medium` for a bounded ambiguity review or more involved extraction. Model choice and effort are separate controls; do not rely on inheriting the main agent's settings. Respect explicit user choices. On other hosts, use an explicitly available lower-cost model/effort equivalent. If the host cannot select a suitable worker, do the task in the main thread and disclose the fallback briefly; do not silently spawn an expensive default.
- Give each worker a fresh, minimal context: one objective, named source files/pages, relevant decisions and constraints, the human-readability rules, and an expected result. Where supported, start without full conversation inheritance (`fork_turns="none"` for Codex's spawn tool). Include enough context to preserve meaning, but not the whole project by default.
- Default to read-only findings or proposed text. For delegated edits, assign explicit, non-overlapping file ownership and keep the main agent from editing those files until the worker returns. Workers must not change shared TODOs, active pointers, navigation, or perform checkpoints. Workers return unresolved work for the main agent to record; they must not delegate further.
- Ask for a concise result: findings or proposed edits, source locations, uncertainties, and checks performed. Stop and report missing context, conflicting evidence, or choices needing design judgment instead of guessing. Escalate those issues to the main agent rather than automatically spawning stronger workers or retrying indefinitely.
- The main agent checks consequential claims against sources, verifies meaning and affected interfaces, integrates accepted results, updates shared records, and checkpoints once. Review the result without repeating the entire delegated task. Record unfinished or failed work honestly. Delegate only when expected benefit exceeds briefing, duplicate context, and integration costs; more agents do not guarantee lower cost.
